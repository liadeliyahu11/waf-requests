# path_dotdot_semicolon

Category: path | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
Rewrites each `../` in the path to `%2e%2e;/`. Dots are percent-encoded so client-side URL preparation cannot normalize them away (measured: raw dot-segments are stripped by `requests` before sending).

## Why the WAF misses it
The edge sees `%2e%2e;/` - no literal traversal sequence to match. If it decodes, it now sees `..;/`, which most rule engines treat as a path-parameter segment rather than a parent-directory step, so traversal signatures do not fire.

## Why the origin still accepts it
Tomcat/WebLogic-family fronting servlets strip path parameters (`;jsessionid=...`) BEFORE resolving dot segments. `..;/` therefore collapses to `/` during routing and the request resolves exactly like the original `../`.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /secret.txt HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

After `path_dotdot_semicolon`:

```http
GET /files/..;/secret.txt HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

## Prerequisites and limits
- Requires a Tomcat/WebLogic/Jetty-family normalizer that strips path parameters first. nginx/Apache/IIS route differently or reject.
- The app must genuinely serve content at the resolved path.
- Differential tier: delivery alone proves nothing - confirm with `verify` or an echo origin.
