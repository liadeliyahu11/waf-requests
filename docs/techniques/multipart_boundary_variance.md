# multipart_boundary_variance

Category: multipart | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: transparent

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform rewrites the Content-Type header so the boundary token becomes quoted (`boundary=XyZ123` becomes `boundary="XyZ123"`) while part delimiters in the body stay byte-identical. RFC 7578 treats both spellings as the same token; lenient parsers accept either form. Naive extractors anchored on one spelling - for example `boundary=(\w+)`, which stops at the quote and captures nothing, or scanners that only parse unquoted forms - lose every part delimiter.

## Why the WAF misses it
Scanners that locate part boundaries with an exact byte comparison against the declared boundary fail to find the parts. With no recognized boundary, body parsing yields nothing to match signatures against, or matches against one blob instead of structured fields.

## Why the origin still accepts it
The body is byte-identical to the original request; only the header spelling changes. Any parser that already handled the original body handles it again - Werkzeug parses the quoted form, which the test suite verifies.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
POST /upload HTTP/1.1
Host: shop.test
Content-Type: multipart/form-data; boundary=XyZ123
Content-Length: 79

--XyZ123
Content-Disposition: form-data; name="q"

' OR '1'='1
--XyZ123--

```

After `multipart_boundary_variance`:

```http
POST /upload HTTP/1.1
Host: shop.test
Content-Type: multipart/form-data; boundary="XyZ123"
Content-Length: 79

--XyZ123
Content-Disposition: form-data; name="q"

' OR '1'='1
--XyZ123--

```

## Prerequisites and limits
- Strict parsers compare the boundary exactly and fail on variance.
- Parsers differ in tolerance; the transform picks a delimiter verified against Werkzeug, not every stack.
- Some intermediaries rewrite the Content-Type header, which breaks the correlation either way.
