# deflate_body

Category: encoding | Risk: conditional | Applies to: aws+cloudflare+akamai | Fidelity: transparent

> **Impact:** **Impact: guaranteed.** Once this transform delivers, a conforming
origin has interpreted the ORIGINAL payload byte-for-byte - the
exploit lands regardless of application stack.

## Mechanism
This transform works like gzip_body but uses the zlib/deflate container. The body is deflated and the `Content-Encoding: deflate` header is set. The wire bytes carry no readable signature.

## Why the WAF misses it
The scanner inspects the raw body bytes and does not inflate deflate-encoded request bodies before matching. Compressed content hides every signature the rules look for.

## Why the origin still accepts it
The origin stack must decompress the body before parsing; that is the documented prerequisite, demonstrated by vulnapp's env-gated middleware. Once inflated, the parser sees the exact original body.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **transparent**).

Original:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 20

{"q": "' OR '1'='1"}
```

After `deflate_body`:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Encoding: deflate
Content-Length: 28

<28 bytes of deflate data>
```

## Prerequisites and limits
- Same prerequisites as gzip_body: the origin must actively decompress request bodies.
- Fails when the WAF inflates the body before scanning.
- Fails when the origin ignores `Content-Encoding`.
- Intermediaries sometimes disagree about raw-deflate versus zlib-wrapped framing, which breaks the origin decode.
