# utf8_overlong_path

Category: unicode | Risk: conditional | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform encodes path separators and dots as overlong UTF-8 byte sequences in percent-encoded form, for example `%C0%AF` for `/` and `%C0%AE` for `.`. The raw path bytes differ from the canonical form while decoding may restore the original characters.

## Why the WAF misses it
Signature engines match path patterns against the received byte string. Overlong sequences break literal anchoring on `/` and `..`, so traversal signatures tied to those bytes do not match.

## Why the origin still accepts it
The attack needs an upstream component that normalizes overlong forms back to their canonical characters while the signature engine does not. On such a stack the router resolves the original path after normalization and serves it.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /a/b.c HTTP/1.1
Host: shop.test
```

After `utf8_overlong_path`:

```http
GET /a%C0%AFb%C0%AEc HTTP/1.1
Host: shop.test
```

## Prerequisites and limits
- Modern routers and decoders usually reject overlong encodings outright; this technique is mostly historical.
- It only helps where normalization and signature matching disagree inside the same deployment.
- A WAF that normalizes the path before matching defeats it.
