# null_byte_terminator

Category: path | Risk: conditional | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
Appends `%00.png` to the request path. The WAF's decoded view ends in a harmless image extension; the NUL byte marks where historic C-string handling stops.

## Why the WAF misses it
Extension-blocklist and file-type rules match the suffix after the last dot. With `%00.png` appended, that suffix is `.png`, so upload/extension rules pass the request.

## Why the origin still accepts it
Stacks using NUL-terminated strings (historic PHP < 5.3.4, C-backed filesystem helpers) truncate at the embedded NUL: filesystem operations act on everything before `%00`. The effective path is the attacker-controlled prefix.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /files/report.txt HTTP/1.1
Host: shop.test
```

After `null_byte_terminator`:

```http
GET /files/report.txt%00.png HTTP/1.1
Host: shop.test
```

## Prerequisites and limits
- Modern runtimes reject embedded NULs outright (Python, Go, current PHP) - this is an educational legacy technique.
- Where it works, interpretation differs from the wire by design; confirm the truncation happened via origin echo.
