# pad_json_ws

Category: size | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: transparent

> **Impact:** **Impact: guaranteed.** Once this transform delivers, a conforming
origin has interpreted the ORIGINAL payload byte-for-byte - the
exploit lands regardless of application stack.

## Mechanism
The transform prepends whitespace bytes inside the JSON document, after the opening `{`. Leading whitespace is valid JSON. The pad length equals the profile's assumed body-inspection limit, so every payload byte starts at or beyond the cutoff.

## Why the WAF misses it
The WAF inspects only the first N bytes of the request body, where N is the configured inspection limit (8 KB fixed on ALB/AppSync for AWS; default 16 KB up to 64 KB on other AWS origins; 128 KB or less on Cloudflare; default 8 KB on Akamai). Inside that window the scanner sees only space characters. No signature matches, so the rule does not fire.

## Why the origin still accepts it
RFC 8259 allows insignificant whitespace between JSON tokens. Any conforming parser skips the padding and reads the full document, including the payload key that sits past the inspected window.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **transparent**).
The inspection window is shrunk to 256 bytes here so
the pad geometry fits on screen.

Original:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 20

{"q": "' OR '1'='1"}
```

After `pad_json_ws`:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 276

<256x ' '>{"q": "' OR '1'='1"}
```

## Prerequisites and limits
- Fails when the operator raised the inspection limit above the assumed profile value.
- Fails when a rule uses `oversize=match` on AWS, because then the truncated slice counts as a match signal.
- On AWS, the truncated body slice can become invalid JSON and trigger the JsonBody fallback action instead.
- The padded body is larger than the caller sent. Very small origin-side document-size caps can reject it.
- The transform assumes the profile limit. Run `find-limit` to confirm the real cutoff first.
