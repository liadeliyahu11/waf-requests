# json_deep_nest_wrap

Category: json_differential | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform wraps the top-level JSON value in roughly 2000 nested arrays. The payload value moves to the innermost position while the document stays valid JSON that the stdlib `json` module parses.

## Why the WAF misses it
Depth-limited scanners and naive recursive regex checks stop well before depth 2000. The payload sits below their cutoff, so signature matching never reaches it.

## Why the origin still accepts it
RFC 8259 sets no nesting limit. Conforming parsers descend the full structure and return the innermost value. The application then reads the payload from its nested position.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 20

{"q": "' OR '1'='1"}
```

After `json_deep_nest_wrap`:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 4019

<2000x '['>{"q":"' OR '1'='1"}<2000x ']'>
```

## Prerequisites and limits
- Changes app-visible shape: the value arrives as a deeply nested array, not at the top level. The application must read through that shape.
- Some production parsers enforce their own depth caps and reject deep input.
- Extremely deep structures cost parse time and memory on both sides.
