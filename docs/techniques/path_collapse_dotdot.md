# path_collapse_dotdot

Category: path | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
Expands each `../` to `%2e%2e%2e%2e//` (encoded form of `....//`). Percent-encoded so the expansion survives client transport.

## Why the WAF misses it
Sanitizers that remove traversal by deleting `../` substrings run their removal pass once over the decoded path. Decoded `....//` becomes `../` after that single pass - the sanitizer re-creates the exact sequence it was meant to delete, and matching already happened against the pre-collapse string.

## Why the origin still accepts it
After the single-pass filter collapses `....//` to `../`, the origin resolves the reconstructed traversal normally. The file reached is the one the original payload named.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /secret.txt HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

After `path_collapse_dotdot`:

```http
GET /files/....//secret.txt HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

## Prerequisites and limits
- Requires a single-pass substring filter (classic hand-rolled sanitizer). Iterative filters or resolvers that never see literal dots are unaffected.
- If nothing strips the dots, the origin receives `....//` literally and 404s.
- Differential tier - confirm interpretation with `verify`.
