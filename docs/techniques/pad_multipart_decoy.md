# pad_multipart_decoy

Category: size | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: additive

> **Impact:** **Impact: guaranteed for the original fields.** Decoys are extra
distinct-name parameters/parts no exploit reads.

## Mechanism
The transform inserts one large decoy part ahead of the original parts in a multipart body. The decoy pushes the attacker-controlled parts past the assumed inspection cutoff. The boundary structure stays valid.

## Why the WAF misses it
The scanner walks the body up to the configured limit (Akamai Kona defaults to 8 KB, settable to 16/32 KB, max 128 KB; AWS ALB/AppSync inspect 8 KB fixed; Cloudflare scans 128 KB Enterprise and less elsewhere). The window fills with the decoy part's bytes, so signatures never see the later parts. Junk-prepending against multipart bodies is publicly demonstrated against Akamai's 8 KB default.

## Why the origin still accepts it
A conforming multipart parser (RFC 7578) walks delimiters to the final boundary and yields every part. Both the decoy and the original parts arrive intact, and named-field semantics stay unchanged.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **additive**).
The inspection window is shrunk to 256 bytes here so
the pad geometry fits on screen.

Original:

```http
POST /upload HTTP/1.1
Host: shop.test
Content-Type: multipart/form-data; boundary=XyZ123
Content-Length: 79

--XyZ123
Content-Disposition: form-data; name="q"

' OR '1'='1
--XyZ123--

```

After `pad_multipart_decoy`:

```http
POST /upload HTTP/1.1
Host: shop.test
Content-Type: multipart/form-data; boundary=XyZ123
Content-Length: 399

--XyZ123
Content-Disposition: form-data; name="waf_decoy"

<256x 'A'>
--XyZ123
Content-Disposition: form-data; name="q"

' OR '1'='1
--XyZ123--

```

## Prerequisites and limits
- Fails when the operator raised the inspection limit above the assumed profile value, unless the decoy grows to match.
- Fails when a rule uses `oversize=match` on AWS.
- The origin application receives the decoy part. File-count limits and strict field allowlists reject it.
- Some upload handlers buffer the whole body before parsing, which costs memory but does not restore detection.
