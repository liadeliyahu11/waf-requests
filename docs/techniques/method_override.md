# method_override

Category: headers | Risk: conditional | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform converts a GET request to POST and adds `X-HTTP-Method-Override: GET`. On the wire the method is POST; the header declares the effective method as GET.

## Why the WAF misses it
Rule conditions are frequently scoped to one method, such as SQLi rules applied only to GET query strings. A POST body carrying the payload does not enter those method-scoped conditions, so the rule set stays silent.

## Why the origin still accepts it
The prerequisite is an origin that honors override headers and rewrites its routing decision accordingly. Flask does not support this natively. Where supported, the application treats the request exactly like the original GET.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /search?q=%27%20OR%20%271%27%3D%271 HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

After `method_override`:

```http
POST /search?q=%27%20OR%20%271%27%3D%271 HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
X-HTTP-Method-Override: GET
Content-Length: 0
```

## Prerequisites and limits
- Conditional: wins only where the origin honors `X-HTTP-Method-Override`. The header is non-standard.
- Fails where the framework ignores the header; the application then sees POST semantics.
- WAFs that inspect all methods uniformly defeat it.
- Side-effecting behavior changes if the origin partially honors the override.
