# percent_double_encode

Category: unicode | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform doubles the percent-encodings in query values: every `%` in a payload-significant byte becomes `%25`. The WAF decodes once and sees encoded noise. An origin that decodes twice recovers the payload.

## Why the WAF misses it
The scanner URL-decodes each parameter value exactly once. After one decode, `%253Cscript%253E` becomes `%3Cscript%3E`, which still contains no literal `<` byte. Signatures anchored on decoded characters do not match.

## Why the origin still accepts it
Some application paths decode twice: for example, an explicit double-unquote, a routing layer that decodes before the framework decodes again, or hand-rolled decoding loops. On those paths the second decode turns `%3Cscript%3E` into `<script>` and the payload lands intact.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /search?q=%27%20OR%20%271%27%3D%271 HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

After `percent_double_encode`:

```http
GET /search?q=%252527%252520OR%252520%2525271%252527%25253D%2525271 HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

## Prerequisites and limits
- Fails on single-decode frameworks. Most frameworks decode once; the page documents this honestly.
- A WAF that decodes repeatedly, or that matches on the raw form too, defeats it.
- Double decoding can corrupt values that legitimately contain `%25`, so benign parameters need care.
