# gzip_body

Category: encoding | Risk: conditional | Applies to: aws+cloudflare+akamai | Fidelity: transparent

> **Impact:** **Impact: guaranteed.** Once this transform delivers, a conforming
origin has interpreted the ORIGINAL payload byte-for-byte - the
exploit lands regardless of application stack.

## Mechanism
The transform compresses the whole request body with gzip and sets the `Content-Encoding: gzip` header. The wire bytes contain the payload only in compressed form.

## Why the WAF misses it
Managed rulesets scan the request body as received and generally do not decompress request bodies before matching. The scanner reads compressed bytes, so no plaintext signature can match inside them.

## Why the origin still accepts it
The prerequisite makes the attack work: the origin stack must decompress request bodies before parsing. This is not default behavior in Flask or Django; the library's vulnapp exposes an env-gated decompression middleware to demonstrate it. After decompression the origin parser sees the original body unchanged.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **transparent**).

Original:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 20

{"q": "' OR '1'='1"}
```

After `gzip_body`:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Encoding: gzip
Content-Length: 40

<40 bytes of gzip data>
```

## Prerequisites and limits
- Wins only where the origin stack decompresses request bodies. Without that middleware the application receives garbage.
- Fails when the WAF decompresses the body before scanning.
- Fails when the origin ignores `Content-Encoding` on requests.
- Some proxies and gateways strip `Content-Encoding` or reject compressed request bodies outright.
