# json_dup_key_lastwins

Category: json_differential | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform emits a duplicate of the first key with a benign value before the original pair or pairs. The document keeps its payload value under the later occurrence of the key.

## Why the WAF misses it
WAF variable extractors that match the first or any occurrence of a key read the benign duplicate and skip matching. The signature never sees the payload value.

## Why the origin still accepts it
Last-key-wins parsers keep the final occurrence of a duplicated name. Most JSON deserializers behave this way, including Python `json` and Jackson by default, so the application reads the payload value.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 20

{"q": "' OR '1'='1"}
```

After `json_dup_key_lastwins`:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 36

{"q":"waf_benign","q":"' OR '1'='1"}
```

## Prerequisites and limits
- Fails against parsers that keep the first value or reject duplicates outright.
- RFC 8259 says object names should be unique and behavior is unpredictable otherwise; strict validators may refuse the document.
- WAFs that match all occurrences defeat it.
- The benign duplicate changes app-visible data if the application iterates raw pairs instead of folding them.
