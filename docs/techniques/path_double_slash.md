# path_double_slash

Category: path | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: transparent

> **Impact:** **Impact: guaranteed.** Once this transform delivers, a conforming
origin has interpreted the ORIGINAL payload byte-for-byte - the
exploit lands regardless of application stack.

## Mechanism
The transform inserts an empty segment `//` inside the path, for example `/search` becomes `/search//x` style splits that collapsing resolvers fold back to the original route. By design it avoids a leading `//`, which would read as protocol-relative and change the request meaning.

## Why the WAF misses it
Non-collapsing matchers compare the literal path string. The inserted empty segment makes the string differ from every anchored form, so path-scoped rules do not match.

## Why the origin still accepts it
Collapsing resolvers treat repeated slashes as one segment separator. They route the request identically to the original path, and the handler sees the same effective route.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **transparent**).

Original:

```http
GET /a/b HTTP/1.1
Host: shop.test
```

After `path_double_slash`:

```http
GET /a//b HTTP/1.1
Host: shop.test
```

## Prerequisites and limits
- Wins only where the router collapses empty segments but the signature engine does not.
- Routers that dispatch on the raw path return 404.
- Some frameworks pass the raw path to handlers, changing app-visible values.
- A leading `//` is deliberately never produced because clients would reinterpret it as a protocol-relative reference.
