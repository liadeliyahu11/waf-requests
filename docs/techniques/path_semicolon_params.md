# path_semicolon_params

Category: path | Risk: standard | Applies to: aws+cloudflare+akamai | Fidelity: differential

> **Impact:** **Impact: conditional.** The wire payload DIFFERS from the original;
the origin interprets it correctly only if its parser behaves as
documented here. Delivery alone is not exploitation - prove it with
`python -m waf_requests verify <url>`.

## Mechanism
The transform appends a `;waf=1` matrix parameter to the first path segment, turning `/search` into `/search;waf=1`. The routing target stays the same on routers that strip matrix parameters.

## Why the WAF misses it
Signature engines match rules bound to specific paths. To a matcher without matrix-parameter awareness, `/search;waf=1` is a new string, so path-scoped conditions anchored on `/search` do not apply and the request escapes rule scope.

## Why the origin still accepts it
Tomcat and Jetty-family routers strip matrix parameters from each segment before routing. After stripping, the effective path equals the original and the handler runs unchanged. RFC 3986 allows `;` as a character inside a path segment, so the form is syntactically valid end to end.

## Wire example

Generated by applying this transform to a representative request (fidelity tier: **differential**).

Original:

```http
GET /search?q=%27%20OR%20%271%27%3D%271 HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

After `path_semicolon_params`:

```http
GET /search;waf=1?q=%27%20OR%20%271%27%3D%271 HTTP/1.1
Host: shop.test
User-Agent: exploit/1.0
```

## Prerequisites and limits
- Wins only where the router strips matrix params but the signature engine does not.
- Routers that route on the raw segment (including the suffix) return 404.
- Some frameworks pass the raw segment to handlers, which changes app-visible path values.
