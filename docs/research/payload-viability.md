# Payload-mutator viability - measured

Per-mutator raw-vs-mutated verdicts against the owned WAFs, generated by
`examples/map_payload_viability.py` (2026-08-26). A mutator is a bypass only
when RAW is BLOCKED and the mutated payload is DELIVERED with the origin
reflecting it. Canonical payloads are per category.

## AWS WAF (owned AWS domain)

| Category | Mutator | Raw | Mutated | Origin |
|---|---|---|---|---|
| sqli | sqli_inline_comment | BLOCKED | **DELIVERED** | reflected |
| sqli | sqli_double_encode | BLOCKED | **DELIVERED** | reflected |
| sqli | sqli_case_toggle | BLOCKED | BLOCKED | - |
| sqli | sqli_version_comment | BLOCKED | BLOCKED | - |
| sqli | sqli_hex_quote | BLOCKED | BLOCKED | - |
| sqli | sqli_whitespace_sub | BLOCKED | BLOCKED | - |
| sqli | sqli_comment_extend | BLOCKED | BLOCKED | - |
| xxe | xxe_utf16_bom | BLOCKED | BLOCKED | - |
| xxe | xxe_parameter_entity | BLOCKED | BLOCKED | - |
| xss/cmdi/lfi/ssrf/ssti | all | DELIVERED | DELIVERED | reflected |

Two payload-level SQLi bypasses measurably beat AWS WAF's SQLi rule:
`sqli_inline_comment` (splits `UNION`->`UN/**/ION`) and `sqli_double_encode`
(percent-double-encodes the payload). Case toggling, version comments, hex
quotes, and whitespace substitution did NOT bypass: AWS WAF normalizes case and
decodes hex literals and comment whitespace before matching (its libinjection
and JSON-aware matching see through them). This matches the normalization
oracle: AWS decodes URL and unicode but is blind to the encodings our two wins
exploit.

Non-SQLi categories (XSS, CMDi, LFI, SSRF, SSTI) have no SQLi-style blocked
baseline on this property, so their DELIVERED rows mean "no rule fires", not
"bypass". XXE is actively blocked and neither mutation escapes it.

## Cloudflare

Same as the request-level matrix: the current managed ruleset blocks only
UA-XSS, so query/body payload vectors are DELIVERED (NO-RULE) and unmeasurable
here. Payload-mutator evidence for Cloudflare requires enabling a body/query
rule on the property.
