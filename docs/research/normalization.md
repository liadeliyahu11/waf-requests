# Normalization oracle - measured decode pipeline

What each WAF decodes (and blocks) vs leaves blind. Method: send the SQLi
payload `' OR '1'='1` in each encoding through `/search?q=` and classify.
BLOCKED = the WAF decoded that representation back to the payload; DELIVERED =
the WAF did not decode it (a blind spot). Generated by
`examples/normalization_oracle.py`, 2026-08-26.

## AWS WAF (owned AWS domain, CloudFront scope)

| Variant | Verdict | Meaning |
|---|---|---|
| raw | BLOCKED | baseline (single percent-encoding) |
| percent | BLOCKED | decodes %XX |
| double | BLOCKED | decodes %25XX too (decodes twice) |
| backslash_unicode | BLOCKED | decodes `\uXXXX` |
| percent_unicode | BLOCKED | decodes `%uXXXX` (IIS-style) |
| html_entity_hex | DELIVERED | blind to `&#x27;` |
| html_entity_named | DELIVERED | blind to `&apos;` |
| overlong_utf8 | DELIVERED | blind to `%c0%af` |
| base64 | DELIVERED | blind to base64 |
| utf7 | DELIVERED | blind to `+ACc-` |
| hex | DELIVERED | blind to `0x27` |

Conclusion: AWS WAF decodes URL-encoding (one and two rounds) and both unicode
escape spellings, but is blind to HTML entities, base64, UTF-7, raw hex, and
overlong UTF-8. This is the mechanical explanation for the measured AWS wins:
`charset_utf7` (no UTF-7 decode), `percent_double_encode` (decodes twice and
matches earlier), and the new payload-level `sqli_double_encode` and
`sqli_inline_comment`.

## Cloudflare (owned Cloudflare domain)

Every variant, including `raw`, was DELIVERED: the current Cloudflare managed
ruleset does not block a query-carried SQLi token at all, so the oracle has no
blocked baseline to map. To map Cloudflare's decode pipeline, a rule that fires
on this vector must be enabled on the property first.
